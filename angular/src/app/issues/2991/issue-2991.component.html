Issue 2991: Screen Reader Accessibility Testing

Testing Instructions

Purpose: Verify that form inputs are correctly announced by screen readers (VoiceOver, NVDA, JAWS) with proper label association, required/optional status, helper text, and error messages.

How to test with VoiceOver on Mac:

  1. Press Cmd + F5 to enable VoiceOver
  2. Use Control + Option + Right Arrow to navigate through elements
  3. When on a form field, press Control + Option + Space to interact
  4. Listen for the announced text and verify it matches expected announcements below

Scenario 1a: Form Item + Input (Basic)

Expected announcement: "Street address, edit text"

Scenario 1b: Form Item + Input with Required

Expected announcement: "Email address, required, edit text"

Scenario 1c: Form Item + Input with Optional

Expected announcement: "Phone number, optional, edit text"

Scenario 1d: Form Item + Input with Helper Text

Expected announcement: "Username, edit text, Enter a unique username between 3-20 characters"

Scenario 1e: Form Item + Input with Error Message

Expected announcement: "Password, required, edit text, invalid, Password must be at least 8 characters"

Scenario 2: Standalone Input with aria-label

Expected announcement: "Search products, edit text"

Scenario 3: Standalone Input with aria-labelledby

Expected announcement: "City name, edit text"

Scenario 4: Negative Control - No Label (Should Fail)

Expected behavior: Screen reader should announce "edit text" with no label - this is an accessibility failure
