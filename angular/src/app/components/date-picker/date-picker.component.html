Timezone Issue Demonstration

This example shows why using strings is better than Date objects for date selection.

❌ Using Date Object (Problematic)

Selected value:

{{ birthdateAsDate | json }}

What gets sent to API (JSON.stringify):

{{ birthdateAsDateJSON }}

⚠️ Problem:

If you select "May 15, 1990" in Mountain Time (GMT-6), it might serialize as "1990-05-15T06:00:00.000Z" or even shift to "1990-05-14" when converted to UTC! Your birthdate changes based on timezone.

✅ Using String (Recommended)

Selected value:

{{ birthdateAsString }}

What gets sent to API (JSON.stringify):

{{ birthdateAsStringJSON }}

✓ Solution:

Always returns "1990-05-15" regardless of timezone. No unexpected date shifts! Perfect for birthdates, event dates, deadlines, etc.

📝 Why This Matters:

  • Birthdates: You were born on a specific calendar date, not a moment in time
  • Event Dates: "Christmas is December 25th" - not "December 24th 11pm UTC"
  • Deadlines: "Submit by March 15th" should be the same date everywhere
  • API Calls: Date objects get converted to ISO strings with timezone info, causing confusion
  • Database Storage: Storing "2024-03-15" is clearer than a timestamp with timezone
